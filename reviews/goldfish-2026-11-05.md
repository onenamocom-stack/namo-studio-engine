# Goldfish Review — measured, fresh context

Run on the phone against `claude-opus-5-5` via the local proxy, with **no conversation
history**: the reviewer saw only the files in this repo. This is the real EGM protocol
(fresh-context reviewer), not a lint pass.

Date: 2026-11-05

---

## BLOCKERS

Ranked by how directly each one stops a correct video from being produced.

1. **HOLE: `namo/agent.py` cannot render any explainer, customer or shot-test brief.**
   - `SCENE_FOR_KIND` maps only `webshow -> gita-ep01`. Every other kind returns `ok: False` from `render()`.
   - `classify()` defaults to `explainer` when no keyword matches, so the default path is always refused.
   - The workflow's own default prompt ("make a 30 second explainer about how Jev mode works") classifies as `explainer` and is refused.
   - 4 of the 5 rows in SPEC's measured table can never produce a film.

2. **CONTRADICTION: in `namo/agent.py`, every webshow brief renders the same Gita episode.**
   - SCENE_FOR_KIND is keyed only by kind. "gita chapter 2 episode 3" renders `gita-ep01`.
   - SPEC's D4 ("the plan is right and the film is wrong") is therefore not fixed. It has been narrowed from "every kind" to "every webshow".
   - `drift.py` now reports D4 as clean, because its regex looks for the literal `scenario = "gita-ep01"`. That line no longer exists, but the behaviour it was meant to catch still does.

3. **CONTRADICTION: `namo/agent.py` crashes with a traceback instead of refusing.**
   - `OUT.mkdir()` is only called inside `render()`, after the scene check and the runtime lookup.
   - On a refusal, `main()` then runs `(OUT / "plan.json").write_text(...)`. On a fresh checkout `out/` does not exist, so this raises `FileNotFoundError`.
   - The "honest refusal" becomes an uncaught crash, and no `plan.json` is written.

4. **CONTRADICTION: the luma check (O1) in `namo/engine.py` is silently off in CI.**
   - `verify_video()` wraps the whole pixel check in `except Exception: return True`.
   - `bootstrap.sh` installs numpy into `.venv`, but both workflows run plain `python3` (setup-python's interpreter), which has no numpy.
   - `import numpy` therefore fails, and every render passes with "luma check skipped". The blank gita-ep01 film SPEC cites would pass.
   - The same `except` also turns a `reshape` error (partial frame bytes) into a pass.

5. **CONTRADICTION: `.github/workflows/namo-agent.yml` publishes rejected films.**
   - "make the video" ends with `|| echo ...`, so the step always succeeds.
   - `publish to R2` runs on `success()`. It globs `out/*.mp4`, which includes a film that `verify_video()` rejected, because the mp4 is written before verification.
   - "Agent-output" also uploads the rejected film as the artifact.
   - This breaks O1 ("the file exists is never success") at the last step.

6. **HOLE: `namo/engine.py` (MgRuntime.render) ignores the plan.**
   - The job passed to the runtime carries only `scene`, `fps`, `workers`, `name` and `seconds`.
   - `ratio`, `style`, `look`, `emotion`, `voice` and the prompt text are never sent.
   - `seconds` is sent but MgRuntime never uses it.
   - The output is whatever the pre-authored scene contains. A "40 sec vertical reel" cannot come out as 40 s or 9:16.

7. **HOLE: `namo/engine.py` and `agent.py` never check duration.**
   - `verify_video()` defaults `min_seconds=0.5`, and `agent.render()` never passes the planned seconds.
   - A 60-second brief that yields a 5-second film passes.
   - SPEC says duration must be >= `min_seconds` and the YAMLs say within 5% of target. Neither is enforced.

8. **HOLE: `namo/agent.py` produces no audio.**
   - `voiceover()` only checks whether piper exists, then returns a note. It never synthesises speech.
   - No audio is muxed. Every film is silent, even though the plan carries a voice id, rate, pitch and pause.

9. **SILENT ASSUMPTION: `namo/mg/scenes/gita-ep01/` exists.**
   - The CLI path (`agent.py`) never checks this. Only `factory.py` does.
   - If it is missing, `shutil.copytree` raises an uncaught exception, before `plan.json` is written.

## SILENT ASSUMPTIONS

**Brief parsing (`namo/agent.py`)**
- **The ratio is read as a duration.** `read_seconds` falls through to `\b(\d{1,2}):(\d{2})\b`, which matches "9:16".
  - "vertical 9:16 explainer" with no duration gives **556 seconds**.
  - The workflow appends the `ratio` input to the prompt, so choosing 9:16 without a seconds override triggers this.
- **Workflow overrides do not override.** `namo-agent.yml` appends overrides to the end of the prompt, but the parsers take the first match.
  - Prompt "30 second ..." with seconds override 60 still gives 30.
  - Prompt "vertical ..." with ratio override 16:9 still gives 9:16, because `vertical` is tested first.
- **"2 min 30 sec" parses as 30 seconds.** The seconds regex runs first and returns its match.
- **Keyword matching is raw substring matching.** Examples:
  - `how` hits "show" and "webshow".
  - `ad` hits "made", "read", "head".
  - `test` hits "latest".
  - `story` hits "history" and forces 9:16.
  - `flat` / `dry` / `fast` hit "flat-motion", "laundry", "breakfast".
  - `namo` (a webshow keyword) hits any brief that mentions the brand.
  - The result is that the kind, ratio and emotion depend on incidental words.
- **Voice override is lost for non-webshow kinds.** `brief.get("voice") or "hi_IN..." if kind == "webshow" else "en_US..."` parses as `(voice or hi_IN) if webshow else en_US`.
- **Dead fallback.** `read_ratio(text) or spec["ratio"]` can never reach the kind's ratio, because `read_ratio` always returns a value.

**Rendering (`namo/engine.py`)**
- `core/render/video.mjs` is assumed to accept `films/<scene>`, `--fps`, `--workers` and `--out <abs path>`. Nothing verifies this upstream CLI.
- `namo/mg/fonts.css` is assumed to exist.
- `bootstrap.sh` fetches fonts into `styles/ink-wash/demo/fonts`. Nothing ties those files to what `fonts.css` references.
- `MgRuntime.available()` says `shutil.which("ffmpeg") or True`, so ffmpeg is never actually required.
- `probe()` never looks for `google-chrome` on PATH. Only the env var rescues it.
- `H3Runtime.render()` returns no `"out"` key. If h3 is ever selected (only possible via `--json` with `runtime: h3`), `agent.render()` crashes on `res["out"]` after a paid GPU run.
- `namo_gpu.py` and `GPU_CONTRACT.json` are expected under `namo/`. The webshow YAML says they live under `manufacture/`.

**Verification (`namo/engine.py`)**
- `verify_video()` uses `max_black_ratio=0.0` with 1-fps sampling. A single flat sampled frame rejects the whole film.
  - That includes a fade-in from black, a title card, or an empty paper frame.
  - The ink-wash scene uses `#F2ECDE` paper, which at 64x36 can easily fall under std 1.0.
  - Good films are likely to be rejected.

**Factory (`namo/factory.py`)**
- **Job ids can mismatch.** `once()` checks for done jobs by `id or prompt`, but `run_job()` names id-less jobs `job-<timestamp>`.
  - Id-less jobs never register as done and re-render every 6 hours.
  - BLOCKED jobs (such as `jev-explainer`) are re-attempted and appended to `status.json` forever.
- **Outputs collide.** All jobs share `out/job.json`, `out/<kind>-<scene>.mp4`, and lemo's `films/<scene>` (which is deleted and recreated on each run). Two webshow jobs overwrite each other.

**Workflows (`namo-agent.yml`)**
- `out_plan.json` and `brief.json` are not valid JSON. `agent.py --dry` prints `[agent] plan:` and `[agent] why:` lines to stdout before the JSON. `brief.json` is never used.
- `engine.py runtimes --probe` always exits 0, so the "engine probe" step cannot fail the job.
- `RUNPOD_KEY` is not passed, so h3 always reports MISSING in that workflow.

## HOLES

- **P1: there is no pipeline loader.** Nothing in `agent.py`, `engine.py` or `factory.py` reads `pipeline_defs/*.yaml`.
  - The rule "must refuse rather than silently no-op" has nothing to apply to. The pipelines are not refused; they are simply never run.
  - Research, script, beat-grid, assets, edit and compose do not exist as code.
- **R1: runtimes are registered unconditionally.** `engine.py` registers both runtimes at import time.
  - SPEC says a runtime is registered only if `probe()` proves it works. The engine docstring claims probe "proves it emits non-blank pixels".
  - In fact `probe()` only checks that files, binaries and env vars exist.
- **B1: the routing table is never tested.** Nothing runs the SPEC table as a test. `drift.py` checks only purity by string search, so "same brief => same plan" and the table itself are unverified.
- **Known drift is not all checked.** `drift.py` has no check for D5 (R2 401). Its runtime loop is a no-op (`for rt in ...: pass`).
- **The GPU claim is not implemented.** `factory.yml` says "exactly one GPU pod per run at most, only if a GPU job is queued". No code counts or limits pods.
- **Nothing routes to h3.** Every kind in `KINDS` has `runtime="mg"`. The `h3`, `rendiv` and `plate` runtimes named in the `agent.py` docstring and the YAMLs are unreachable from a brief, and `rendiv`/`plate` do not exist.
- **The "done" checklist cannot pass.** SPEC's first item, "`engine.py runtimes --probe` all READY", cannot be met in `namo-agent.yml`, because h3 has no key there.

## CHALLENGES TO THE SPEC

- **The drift table is stale.**
  - D4 is described as "falls back to gita-ep01 for every kind". The code now refuses non-webshow kinds instead.
  - README says "15 pipeline skill references" are missing. SPEC says 17 (8+9) plus 1 (D3), which is 18.
  - SPEC claims "tested 7/7" but the table has 5 rows.
  - Leaving these unreconciled lets the true residual D4 (every webshow brief gets ep01) disappear from both the doc and the drift check.
- **`drift.yml` is permanently red.** D1–D3 are known and accepted, so the check never passes and a new regression cannot be distinguished from the baseline. `factory.yml` already downgrades drift to a warning.
  - The spec needs a known-drift allowlist, or the gate is noise.
- **The "explainer" kind is defined twice, incompatibly.**
  - `namo-explainer.yaml` describes a 20–40 minute video with chapters of 90–420 s.
  - The router sends "30 second explainer" to the same kind and sets `chapters: true`.
  - A 30 s film cannot satisfy a 90 s chapter minimum.
- **The webshow format contradicts itself.**
  - `namo-webshow.yaml` sizes subtitles for "1920 width" (landscape) and the router gives webshow 16:9.
  - `GPU_CONTRACT` stems are 480x864 (portrait).
  - SPEC never says which one wins.
- **The plan has nothing to render from.** SPEC's brief contract derives `style`, `emotion`, `voice` and `ratio`, but the runtime contract (`render(job, outdir)`) defines no job schema that carries them.
  - SPEC should define the job shape. Otherwise "nothing downstream re-decides" is trivially true, because downstream never receives the decision at all.
- **The blank-frame rule has no threshold.** "Sampled frames must not be flat" does not say how many frames, or how flat. With zero tolerance at 1 fps, a single legitimate fade fails the whole film.

## VERDICT

**No.**

- **Explainer, customer and shot-test briefs, and any brief with no matching keywords:** the router refuses them. On a fresh checkout that refusal then crashes on the missing `out/` directory.
- **Webshow briefs:** these can only ever produce one fixed, silent, pre-authored scene (`gita-ep01`), and only if that directory exists, which is not shown. Chapter, episode, duration and ratio are all ignored.
- **The pixel guard:** in CI it is effectively disabled, because numpy is installed only in the venv and every exception counts as a pass.
- **Publishing:** the agent workflow swallows failures and publishes whatever mp4 is in `out/`.

A brief can produce a plan today. It cannot produce a video that matches the brief.
